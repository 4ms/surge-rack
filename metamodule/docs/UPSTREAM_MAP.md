# How the port uses Surge

The port compiles Surge's own DSP sources from the `surge` submodule. No Surge code
is copied into `metamodule/`. Changes that the sources need live as commits in the
4ms forks of Surge and its libraries. The `metamodule/` tree supplies only:
- small stand-ins for the desktop infrastructure the sources include;
- per-module engines (`dsp/*_dsp.cpp`);
- processors, panels and registration.

| | `effects/{Vocoder,Resonator,Combulator,FrequencyShifter,Treemonster,RotarySpeaker,Distortion,RingModulator,Reverb2,BBDEnsemble,Nimbus}Effect.cpp` |

`surge/resources` by `cmake/embed_tables.cmake`.

## Stand-ins (`dsp/compat/`)

`dsp/compat` precedes `surge/src/common` on the include path, so these headers replace
Surge's own for every source that includes them by name. Headers in a source's own
directory are always found first and cannot be replaced this way;
`ModulationHelpers.h` handles that case for the LFO.

| File | Replaces | Provides |
| --- | --- | --- |
| `SurgeStorage.h`, `SurgeStorage.cpp` | `SurgeStorage.h`, plus the parts of `Parameter.h` the DSP uses | Sample rates; Surge's 12-TET pitch, omega, dB and envelope-rate lookup tables (shared with the sst-effects hosts through `filter_tuning.h`, `db_table.h`, `modulation_clock.h`); waveshape lookups; random sources; `Parameter`, `FxStorage`, `OscillatorStorage`, `LFOStorage` and the step-sequencer storage. Patch, tuning library, filesystem and GUI hooks are compile-only stubs. |
| `ParameterRanges.h` | `Parameter::set_type`'s ranges | Generated by `tools/gen_parameter_ranges.py` from `Parameter.cpp`, for the control types the compiled sources and engines use. |
| `SurgeMemoryPools.h` | `SurgeMemoryPools.h` | String's delay-line pool, as plain heap allocation. |
| `Tunings.h` | tuning-library's `Tunings.h` | `MIDI_0_FREQ`. |
| `ModulationHelpers.h` | `MSEGModulationHelper.h`, `FormulaModulationHelper.h` | Aborting stand-ins; the LFO panel offers neither shape. |
| `SurgeVoiceState.h` | `SurgeVoiceState.h` | An empty voice state. |
| `juce_dsp/juce_dsp.h` | JUCE | The heap block, audio block and `SIMDRegister<float>` used by chowdsp's delay lines and the Spring Reverb. |

Rerun `tools/gen_parameter_ranges.py` after updating Surge, and whenever an engine or
compiled source starts using a new `ct_` control type.

## Engine-side adaptations

Engines create effects and oscillators the way Rack's FX and VCO modules do, through
`init_ctrltypes()` and `init()`. MetaModule-specific behaviour stays in the engines
rather than in Surge:
- **Native resets.** `effect_host.h`'s `reset_effect` rebuilds an effect in place when its
  constructor does not allocate. Otherwise a small subclass resets the state, which the
  fork made `protected`.
- **Rack-import compatibility modes** (shared engines, clocks, triggers, envelope rates
  fixed at creation).
- **Per-voice seeds**, and Combulator's shared import noise.
- **Rotary's horn-rate bounds.**
- **Nimbus's trigger latch.**
- **Spring's 192 kHz shake-buffer reservation.**

Target-wide definitions (`CMakeLists.txt`) size buffers for a 192 kHz ceiling. The
desktop defaults are larger:
- `SURGE_REVERB2_MAX_ALLPASS_LEN=32768`
- `SURGE_SPRING_DELAY_SIZE=32768`
- `SURGE_SPRING_ALLPASS_DELAY_SIZE=1024`

- **Bug fixes** apply to desktop Surge as well.
- **Hooks** add access or configuration without changing default behaviour.
- **Size and performance** changes are output-identical.

## Updating Surge

1. Rebase each fork branch onto the new upstream.
2. Update the submodule pointers.
3. Rerun `tools/gen_parameter_ranges.py`.
4. Build. Stand-in members that a new upstream needs show up as compile errors in `dsp/compat`.
5. Compare engine output before and after the update with a render harness that drives
   every registered processor deterministically. Changes should come only from upstream
   DSP changes you intend to take.
