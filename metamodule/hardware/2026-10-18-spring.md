# Spring Reverb hardware optimization — 2026-10-18

Development **0.1.47** removes the overload observed in the fixed Spring demo.
Spring has no oversampling. The change preserves its network and control cadence:
the four-lane type stores a native SIMD register with float alignment, reflection
tap interpolation is prepared at control rate, and unchanged filter/allpass
coefficients are cached. RNG, Chaos smoothing and Knock still advance normally.
Preparation invalidates the caches, including Rack partial initialization.
The upstream Surge sources are unchanged. This PR carries the optimized adapter
and checked-in runtime headers; the development build generates those headers.

## Physical device

USB004, 48 kHz, 256 samples, same Classic stimulus and original fixed demo patch.
CPU percentages include the entire patch. Each final live case ran for 30 seconds.

A separate five-second buffered capture confirms the final fixed patch:
**71.40% mean, 73.81% peak, 0/940 overruns**.
Maximum sets Size, Decay, Reflections, Spin, Damping, Chaos and Mix to one.
Modulated fans Classic audio into every continuous Spring CV input and the Knock
gate, forcing coefficient changes. These remain single stereo-voice tests.
No claim is made for maximum polyphony, every setting/sample rate, or analog audio.
